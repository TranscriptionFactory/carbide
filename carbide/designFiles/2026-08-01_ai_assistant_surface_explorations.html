Carbide · Design Exploration — Assistant Surfaces, Round 2

Where else the one assistant appears

The base mockup unified the three existing docks. These five explorations are additional projections of the same assistant — each one rides an existing Carbide mechanism (omnibar, status bar, tabs, editor gutter, action registry) and an already-planned phase, so none of them creates new AI machinery.

1 · Omnibar — Ask mode

rides omnibarneeds P0–P2

The omnibar is already the app's universal entry point. An Ask segment makes the assistant reachable from anywhere without opening a dock: retrieval-backed answers with citations, then either dissolve (esc), insert at cursor, or promote to a full chat session. This is the "assistant at your fingertips" surface — presence without chrome.

2 · Status bar presence + runs popover

rides status barneeds P0

The run kernel decouples run lifetime from UI lifetime — which means runs need a home that isn't a dock. A persistent presence cell in the status bar shows readiness and live run count; its popover lists every active run with a stop control, including runs whose originating surface is long closed. This is the daemon made visible.

3 · Proposal review center

rides tab systemneeds P1 + P3

The proposal queue's full-size projection: a tab that collects every pending proposal across sessions and surfaces — panel edits, agent file-ops, ambient fixes — grouped by provenance, reviewed hunk-by-hunk, applied against a git checkpoint. The staging-area mental model users already have from git, pointed at AI edits.

4 · Margin annotations

rides editor gutterneeds P3 + P6

Ambient findings anchored where they apply instead of interrupting as toasts. The reactor attaches notes to blocks — a stale link, a contradiction with another note — rendered in a quiet margin rail. Each card is provenance-tagged and resolves into the same proposal queue. Nothing here generates text into the note unasked; annotations only ever offer.

Hybrid retrieval

Retrieval fans out to two engines in parallel: FTS5 for exact terms and the embedding index for semantic neighbors, merged through Reciprocal Rank Fusion.

  • RRF constant k=60, unvalidated against [[rrf-weights]]
  • Block hits folded in after note-level dedup

Scope filters apply before fusion, so a folder-scoped query never sees out-of-scope embeddings.

5 · Session as tab

rides tab systemneeds P1

The sidebar is right for quick asks, cramped for long agent sessions. Once sessions are first-class (P1), any session can open as a tab — full-width transcript, expanded tool trails, room for diffs — via "Open as tab" in the session list. Same store, same session id; the sidebar and the tab are two views of one conversation, never a fork.

All five mocked surfaces are projections of the same kernel/session/proposal stores — no new AI machinery, no second assistant. Ordering intuition: 2 falls out of P0 nearly free · 1 and 5 unlock at P1–P2 · 3 at P3 · 4 last, gated on ambient opt-in.
